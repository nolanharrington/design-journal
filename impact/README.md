# Impact and outcomes

Use [the impact template](../templates/impact.md) for `short-measure-name.md`.
Record completed work and the user or product change observed, supported by
approved public-safe evidence. Examples of useful measures include task
completion time, accessibility barriers, error frequency, or confidence in a
workflow. Do not frame predicted or hypothesized outcomes as impact.

If a change has not been quantified, suggest an appropriate metric or evidence
source to find, or a measure to start tracking. These are ways to investigate or
quantify change, not predictions about results. Record the metric definition,
baseline or comparison period when available, method, timeframe, and source.
Collect manually at first; this template does not fetch analytics. Append dated
observations so changes and uncertainty remain visible.

Distinguish activities and outputs (such as delivering a prototype) from outcomes
(such as fewer errors). Qualitative evidence is useful when appropriately
qualified. No baseline or no measurement should be stated explicitly, never
converted into an invented result. Include attribution limits and relevant
guardrails.
