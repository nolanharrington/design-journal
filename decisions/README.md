# Design decisions

Record choices that materially affect the product experience, design strategy,
scope, or quality. Use [the decision template](../templates/decision.md) and name
records `DEC-001-short-topic.md`, increasing the number within this project.

Explain why the chosen option fit the context, not just what was chosen. Include
alternatives, trade-offs, evidence, and conditions for revisiting the choice.
Design decision records are not software architecture approval records.

Keep a record of changed decisions: mark the earlier record superseded and link
to the replacement rather than erasing the history. Decision state (proposed,
accepted, superseded) is separate from frontmatter document review status.
